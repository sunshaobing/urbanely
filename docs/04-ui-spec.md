# UI Spec

## 1. 方向

运营台要像“现场服务控制台”，不是营销网站。信息密度高、扫描快、状态清楚、操作直接。

关键词：

- 安静
- 可靠
- 证据优先
- 风险优先
- 手机可用

## 2. 视觉

- 背景：暖灰绿 `#f4f5f2`
- 主文字：墨色 `#17201d`
- 主色：深青 `#0f766e`
- 主色浅底：`#e6f4f0`
- 风险色：红 `#b42318`、橙 `#b45309`
- 信息色：蓝 `#2563eb`
- 字体：系统中文字体，数字使用等宽数字特性
- 圆角：卡片和按钮不超过 8px
- 阴影：只用于浮层、抽屉、报告纸张

## 3. 布局

- 桌面：左侧导航 232px，顶部工具栏 64px，内容区最大宽度 1440px。
- 平板：导航折叠为图标。
- 手机：底部导航，表单单列，主操作固定在底部。

## 4. 导航

1. 运营工作台
2. 勘测单
3. 封堵单
4. 服务单
5. 客户与门店
6. 报告中心

现场作业统一迁移到微信小程序；Web 管理端不再提供“现场模式”页面或导航入口。

## 5. 关键页面

### 5.1 工作台

- KPI 条：待整改、今日作业、逾期复检、封堵闭环率。
- 今日作业表：时间、门店、类型、负责人、状态。
- 风险队列：极高/高风险、逾期、证据缺失。
- 服务趋势：按周/月。
- 高频隐患：类型排行。

### 5.2 勘测单列表

- 搜索、状态分段筛选、风险筛选。
- 列：编号、门店、日期、风险、状态、负责人、复检日期。
- 行点击进入详情。

### 5.3 勘测单详情

- 顶部：编号、状态、风险、主要操作。
- Tab：现场信息、结构隐患、治理方案、影像证据、报告预览。
- 现场信息：门店、地址、日期、时间段、勘测人员、门店对接人、联系电话、范围 chips。
- 结构隐患：隐患点列表，可添加、编辑、标记严重度。
- 治理方案：四个文本区 + 模板插入。
- 影像证据：统一为“结构风险图片”，桌面端一行 5 张，行数随图片数量自动增减；支持多选批量上传，最多 100 张；不再展示封堵前/后照片。
- 签字确认：勘测人员先签，再把同一台手机交给客户代表签；两笔签名都完成后才能锁定报告。
- 报告预览：A4 纸张。

### 5.4 封堵单详情

- 顶部：编号、状态、关联勘测单。
- 步骤条：立项、施工、影像、验收、复检。
- 施工信息表单。
- 封堵部位列表：每个部位有前/后照片、材料、结果。
- 材料明细表。
- 验收与签字区。
- 封堵责任人先签，再把同一台手机交给客户代表签；签字使用手机手写签名板。

封堵前/后照片只出现在封堵单的封堵部位中，用于施工验收；勘测单只保留结构风险图片。

### 5.5 报告中心

- 左侧模板列表。
- 中间 A4 预览。
- 右侧版本、生成记录、下载、二维码。

## 6. 组件规则

- 状态用 pill，不用整行底色。
- 风险用色 + 文本，不只靠颜色。
- 表格行高 44-52px。
- 图标按钮必须有 tooltip 或 aria-label。
- 破坏性操作只出现在详情页，并二次确认。
- 空状态给下一步动作，不写空话。

## 7. 打印

- A4 210mm × 297mm。
- 页边距 14mm。
- 页眉 logo 与公司名称作为整体居中；报告编号和页码固定在右上角。
- 正文 9-10pt，标题 14-18pt。
- 表格线 0.5px，页脚包含公司信息、页码、报告编号。
- 打印时隐藏导航、按钮、提示。
- 签名区保留足够高度。

## 8. 整体壳层

- 侧边栏按“运营 / 主数据 / 现场”分组，并展示当前工作空间、今日风险和同步状态。
- 顶栏统一承载面包屑、系统运行状态、全局搜索、快捷命令、新建入口和用户角色。
- `Ctrl/⌘ + K` 打开快捷命令，可跳转页面或发起勘测、封堵、报告等操作。
- 工作台使用“KPI + 闭环运行图 + 今日作业 + 风险队列”的信息层级。
- Web 管理端数据由统一实时 Provider 提供：12 秒轮询、窗口聚焦立即刷新、写操作完成后强制刷新；页面不得用本地示例数据替代生产数据。
- 勘测单和封堵单详情统一使用记录头部、工作流轨道、页签和右侧摘要。
- 图片网格在桌面端一行 5 张，行数随数量自动增减；手机端保持两列。
- 平板宽度下侧栏折叠；手机端使用底部导航；表格在窄屏内部横向滚动，不撑破页面。

## 9. 人员与权限

- 导航管理组提供“人员与权限”，面向管理员和运营负责人。
- 人员页展示角色、负责范围、状态、最近活跃时间和门店授权。
- 人员头像使用本地生成的卡通头像，按姓名稳定生成，不依赖外部图片服务。
- 人员详情支持修改角色、数据范围、状态和负责门店。
- 角色权限页按“模块 × 查看/新建/编辑/审核/导出”展示权限矩阵。
- 敏感操作单独管理：完整电话、合同附件、原始签名、报告导出、修改权限、作废单据。
- 审计记录展示操作人、动作、对象、结果和详情，已阻止的操作使用红色状态。
- 权限变更必须保存后才生效，并提示写入审计日志。

## 10. 登录页

- 手机号 + 密码登录，手机号使用 +86 前缀和 11 位数字校验。
- 支持显示/隐藏密码、保持登录、忘记密码提示和登录错误反馈。
- 登录成功后进入运营工作台；顶栏提供退出登录。
- 桌面端使用品牌信息、业务统计和流程提示组成左侧视觉区，右侧为登录表单。
- 手机端隐藏左侧品牌区，只保留品牌标识和登录表单。
- 原型使用演示登录，只校验手机号和密码格式；生产环境必须改为服务端认证、密码哈希、登录限流和会话审计。

## 11. 微信小程序现场端

- 现场端使用 uni-app + Vue 3 实现并编译微信小程序，旧原生版本只保留为参考。
- 现场端主色为绿色：深森林绿顶部现场区、浅鼠尾草绿页面底色、绿色主操作；风险、待处理和已完成仍保留柔和红/橙/绿状态色，避免信息层级丢失。
- 企业 LOGO 与组织名称从后端模板接口读取；加载失败时显示后端同款盾牌标识。人员头像按姓名稳定生成卡通形象，规则与生产 Web 端一致，不使用随机网络头像。
- 页面包括登录、工作台、任务详情、现场勘测、封堵记录、报告归档、个人中心和修改密码。
- 底部导航固定为“任务 / 勘测 / 封堵 / 报告 / 我的”，面向现场师傅优先暴露勘测和封堵入口；详情页使用流程步骤条和底部固定操作区。
- 角色导航：勘测人员只显示“勘测 / 我的”，封堵人员只显示“封堵 / 我的”，管理角色显示完整五项导航；现场人员不显示报告管理入口。
- 数据范围：勘测人员按 `engineer_id/engineer_name` 匹配自己的任务，封堵人员按 `supervisor/assignee/operator` 或封堵单 `service_person` 匹配自己的任务；任务统一分为“未完成 / 已完成”。
- 任务详情的流程轨道按角色裁剪：勘测人员只看到勘测、勘测双签和勘测审批；封堵人员只看到接单、签到、施工前后影像、封堵双签、封堵审批和报告生成。
- 工作台使用简约商务风：绿色顶栏、白色任务卡片、8px 圆角、浅灰阴影，间距按 8px 倍数组织。
- 标题 18px 加粗，正文 14px，辅助文字 12px。
- 待处理、进行中、已完成分别使用柔和红、橙、绿浅底色，不使用高饱和色块。
- 工作台顶部展示现场人员、日期、本月任务、待审核、到期复检；随后展示服务端封堵部位汇总、状态分段筛选和任务卡片。
- 状态筛选必须请求服务端 `/api/workorders?status=...`，前端不自行过滤任务。
- 汇总数字直接使用 `/api/dashboard/summary` 返回值，前端不统计业务指标。
- 底部导航使用深森林绿底，选中项图标、文字和顶部指示线使用白色。
- 任务详情展示客户、服务地址、联系人电话、封堵部位、材料和审核退回原因；底部固定“开始勘测 / 封堵记录”两个现场动作。
- 任务详情顶部展示完整 11 步业务轨道，当前节点由服务端勘测单与封堵单状态计算，底部只显示当前可执行的一个主操作。
- 业务轨道：现场勘测 → 勘测报告双签 → 勘测审批 → 派单给封堵 → 封堵接单 → 现场签到 → 施工前影像 → 施工后影像 → 封堵报告双签 → 封堵审批 → 生成报告。
- 审批人看到“审批勘测报告 / 派单给封堵 / 审批封堵报告”，非审批角色显示等待状态；封堵责任人看到“封堵接单 / 现场签到 / 施工影像 / 双签”。
- 每次操作成功后重新请求服务端关联单据，刷新轨道；前端不把点击结果直接当作审批完成。
- 勘测流程：现场信息 → 风险点 → 结构风险图片 → 治理方案 → 签字提交。
- 结构风险图片支持拍照和相册批量选择，单次最多 9 张，累计硬上限 100 张；手机端一行 5 张，行数随图片数量自动增减。
- 封堵流程：服务信息 → 材料与部位 → 封堵前后照片 → 服务记录 → 签字提交。
- 勘测单只展示结构风险图片；封堵前/后照片只出现在封堵记录。
- 签字使用 Canvas 手写：勘测人员 + 客户代表、封堵责任人 + 客户代表，均在责任人手机上依次完成。
- 草稿同时写入本机和服务端 `drafts`。上传中的照片、签名和未提交表单必须显示为草稿或待同步状态，不能伪装成已提交。
- 现场采集使用生产接口：勘测 `risk-surveys`、封堵 `service-reports`、上传、签字、提交和 PDF；接口地址集中在统一 API 客户端。
- 报告归档页分别读取 `risk-surveys` 和 `service-reports`，支持服务端关键词检索与 PDF 打开；不再把“已完成作业单”当作报告列表。
- 登录页使用手机号 + 密码提交生产 API，只保存访问令牌，不保存密码，也不在小程序代码中内置管理员凭据。

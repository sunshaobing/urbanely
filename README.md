## 申汰 PCO 现场服务系统

这是一个基于两份飞书打印单据逆向出来 PCO（有害生物防制）现场服务系统设计，包含可操作的前端原型、业务 PRD、技术规格、数据模型、API 契约和飞书迁移映射。

### 先看什么

1. `PRD.md`：业务问题、角色、流程、MVP 范围和验收标准。
2. `Tech-Spec.md`：架构、技术栈、离线同步、报告生成、权限和部署。
3. `docs/01-reverse-engineering.md`：飞书 Base 与两份 PDF 的逆向证据。
4. `docs/02-data-model.md`：核心实体、状态机、索引和迁移映射。
5. `docs/05-feishu-field-map.csv`：86 个飞书字段的逐项迁移建议。
6. `app/`：可交互原型。

### 微信小程序现场端

`uniapp/` 是新的 uni-app + Vue 3 + TypeScript 现场端，使用统一页面代码编译微信小程序。`miniprogram/` 保留为旧原生版本参考，不再作为主开发入口。

已实现页面：

- 登录：手机号 + 密码提交到生产 `/api/auth/login`，访问令牌保存在微信本机。
- 工作台：绿色现场控制台、服务端汇总指标、待处理/进行中/已完成任务筛选和任务详情。
- 现场导航：底部固定“任务 / 勘测 / 封堵 / 报告 / 我的”，师傅可直接进入勘测和封堵任务列表，不需要先进入管理式工作台。
- 任务详情：客户联系人电话、服务地址、封堵部位、材料明细和审核退回原因，展示从勘测到报告生成的 11 步业务轨道。
- 现场勘测：现场信息、风险点、结构风险图片、治理方案、勘测人员与客户代表手写签字，支持本机和服务端草稿。
- 封堵记录：服务信息、材料与部位、封堵前后照片、服务记录、封堵责任人与客户代表手写签字。
- 报告归档：分别读取勘测记录和封堵记录，支持服务端关键词检索和 PDF 打开。
- 我的：账号角色、服务端统计、网络同步状态、修改密码和退出登录。

当前页面统一调用现有腾讯云后端 `https://sunrgw.cn`。工作台只负责渲染服务端返回的状态、筛选结果和汇总数据，不在前端计算任务状态或业务指标。勘测和封堵页面使用 `risk-surveys`、`service-reports`、上传、签字、提交、草稿和 PDF 接口。

企业 LOGO 与公司名称优先读取 `GET /api/templates`，接口失败时显示后端同款盾牌标识。人员头像按姓名稳定生成卡通形象，规则与生产 Web 端一致。

现场角色隔离：

- `engineer / service_engineer`：勘测人员，只显示“勘测 / 我的”和分配给自己的任务。
- `sealing_engineer`：封堵人员，只显示“封堵 / 我的”和分配给自己的任务。
- `admin / supervisor / super_admin`：管理角色，可查看完整任务、勘测、封堵和报告入口。
- 每位现场人员在任务列表中只看到“未完成 / 已完成”两组；跨角色页面和他人任务会被路由守卫退回自己的工作台。

主流程：

`勘测 → 勘测报告双签 → 勘测审批 → 派单给封堵 → 封堵接单 → 现场签到 → 施工前影像 → 施工后影像 → 封堵报告双签 → 封堵审批 → 生成报告`

### 原型包含

- 运营工作台：待整改、今日作业、逾期复检、封堵闭环率、风险队列。
- 勘测单：现场信息（含门店对接人电话）、结构隐患、治理方案、结构风险图片批量上传（最多 100 张，桌面端一行 5 张自动换行）、A4 报告预览。
- 封堵单：施工信息、封堵部位、材料明细、验收与签字、4 页报告预览。
- PCO 服务单：服务内容、物料、证据完整度、签字缺口。
- 客户与门店：合同状态、风险分、未闭环隐患、最近单据。
- 报告中心：勘测报告 2 页、封堵服务单 4 页、版本历史、打印/PDF。
- 现场模式：手机端离线采集演示、隐患拍照、客户签字、本机队列。
- 手机手写签字：勘测人员 + 客户代表、封堵责任人 + 客户代表，双方签字图片写入报告。
- 移动端底部导航和 390px 视口适配。
- 整体运营壳层：分组导航、工作空间、`Ctrl/⌘ + K` 快捷命令、闭环运行图和详情页工作流轨道。
- 人员与权限：卡通头像、人员角色、门店范围、模块动作矩阵、敏感操作开关和审计记录。
- 登录页：手机号 + 密码、保持登录、退出登录和会话恢复；原型使用演示认证。
- uni-app 现场端：绿色现场控制台、Vue 3 多页面结构、腾讯云 API、5 列结构风险图片网格、双人手写签字、报告 PDF 归档和深森林绿底部导航。

### 核心设计判断

- 不克隆飞书表格，改为领域模型。
- 以 `Finding`（隐患点）串联勘测、封堵、复检、报告和证据。
- 用主数据、模板和自由文本替代 208/130/111 个多选长文本选项。
- 报告是结构化数据的不可变快照，不是业务数据源。
- 高风险、逾期复检、证据缺失进入运营队列，而不是埋在表格筛选里。

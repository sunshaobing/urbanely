# urbanely
我是一个办公与软件开发者

## 申汰 PCO 现场服务系统

这是一个基于两份飞书打印单据逆向出来 PCO（有害生物防制）现场服务系统设计，包含可操作的前端原型、业务 PRD、技术规格、数据模型、API 契约和飞书迁移映射。

### 先看什么

1. `PRD.md`：业务问题、角色、流程、MVP 范围和验收标准。
2. `Tech-Spec.md`：架构、技术栈、离线同步、报告生成、权限和部署。
3. `docs/01-reverse-engineering.md`：飞书 Base 与两份 PDF 的逆向证据。
4. `docs/02-data-model.md`：核心实体、状态机、索引和迁移映射。
5. `docs/05-feishu-field-map.csv`：86 个飞书字段的逐项迁移建议。
6. `app/`：可交互原型。

### 运行原型

```bash
cd app
pnpm install
pnpm dev
```

打开 `http://127.0.0.1:5173/`。

验证命令：

```bash
pnpm typecheck
pnpm build
```

### 原型包含

- 运营工作台：待整改、今日作业、逾期复检、封堵闭环率、风险队列。
- 勘测单：现场信息（含门店对接人电话）、结构隐患、治理方案、结构风险图片批量上传（最多 100 张，桌面端一行 5 张自动换行）、A4 报告预览。
- 封堵单：施工信息、封堵部位、材料明细、验收与签字、4 页报告预览。
- PCO 服务单：服务内容、物料、证据完整度、签字缺口。
- 客户与门店：合同状态、风险分、未闭环隐患、最近单据。
- 报告中心：勘测报告 2 页、封堵服务单 4 页、版本历史、打印/PDF。
- 现场模式：手机端离线采集演示、隐患拍照、客户签字、本机队列。
- 手机手写签字：勘测人员 + 客户代表、封堵责任人 + 客户代表，双方签字图片写入报告。
- 移动端底部导航和 390px 视口适配。
- 整体运营壳层：分组导航、工作空间、`Ctrl/⌘ + K` 快捷命令、闭环运行图和详情页工作流轨道。
- 人员与权限：卡通头像、人员角色、门店范围、模块动作矩阵、敏感操作开关和审计记录。
- 登录页：手机号 + 密码、保持登录、退出登录和会话恢复；原型使用演示认证。

### 核心设计判断

- 不克隆飞书表格，改为领域模型。
- 以 `Finding`（隐患点）串联勘测、封堵、复检、报告和证据。
- 用主数据、模板和自由文本替代 208/130/111 个多选长文本选项。
- 报告是结构化数据的不可变快照，不是业务数据源。
- 高风险、逾期复检、证据缺失进入运营队列，而不是埋在表格筛选里。

- 客户项目 186 条，服务单 195 条，工程师 14 条，防治方案 7 条。
- 服务单高风险 88 条、极高风险 1 条。
- 合同附件覆盖 0/186，客户到服务单关联 54/186，客户到封堵报告关联 56/186。
- 封堵表 `tblT6csxWufRBW2e` 对 guest 不可读，字段根据 PDF 推断。

### 限制

- 原型使用本地示例数据，没有生产后端、数据库、登录、对象存储和真实离线同步。
- 示例中的电话和联系人已脱敏，不使用真实客户隐私数据。
- 要把原型变成生产系统，下一步是按 `Tech-Spec.md` 建 PostgreSQL/Prisma 数据层、附件存储、报告任务和迁移脚本。
